# Работа с Netlane

## Перед изменениями

- Прочитайте [архитектуру](docs/ARCHITECTURE.md) и [инструкции разработки](docs/DEVELOPMENT.md).
- Основная ветка — `main`. Не переписывайте опубликованную историю и теги релизов.
- Не добавляйте пароли, ссылки подписок/приглашений, приватные ключи, базы, сертификаты и данные реальных пользователей. Для примеров используйте `example.com`.

## Изменения и проверки

- Делайте небольшие изменения с понятным назначением и сообщением коммита.
- Выполняйте относящиеся к изменению проверки локально; CI запускается на каждый push и pull request.
- Для Go используйте `gofmt`, для текста — настройки `.editorconfig`.
- Сохраняйте совместимость конфигураций и данных. Изменения форматов, восстановление и обновление описывайте отдельно.
- Не меняйте рабочие VPS при разработке и тестировании; используйте локальные изолированные стенды.
- Обновляйте документацию и `CHANGELOG.md` вместе с поведением.

## Выпуск

Только через workflow Release: раздел версии в `CHANGELOG.md`, затем Actions → Release с тегом `netlane-X.Y.Z`. Опубликованный релиз сразу видят все серверы; проверочные сборки публикуйте как pre-release. [Подробнее](docs/DEVELOPMENT.md#ci-и-выпуск).

Для сообщений об ошибках доступны шаблоны Issues; для уязвимостей используйте [политику безопасности](SECURITY.md).
