# Ноды и подписка

Главный сервер (main) хранит пользователей и панель. Ноды — VPN-серверы в других локациях:
они получают пользователей с main и сами держат их в актуальном состоянии. Пользователь
один и тот же во всех локациях, а клиент получает их все по одной ссылке подписки.

## Добавить ноду

1. Нужен новый VPS (Ubuntu 24.04/26.04 или Debian 13, x86_64) и свой домен с A-записью на его
   IP. Домен ноды не совпадает с доменом main.
2. В панели main: «Ноды → Добавить ноду». Панель покажет команду с кодом приглашения: он
   действует 24 часа и подходит для одной ноды.
3. На новом VPS от root положите `trusttunnel-dev.tar.gz`, `.sha256` и `.sig` из релиза в `/root` и выполните команду из
   панели:

   ```sh
   cd /root && sha256sum -c trusttunnel-dev.tar.gz.sha256 && printf '%s\n' <открытый ключ> >netlane-release.pub && openssl dgst -sha256 -verify netlane-release.pub -signature trusttunnel-dev.tar.gz.sig trusttunnel-dev.tar.gz && netlane_node_dir=$(mktemp -d /root/netlane-node.XXXXXX) && tar -xzf trusttunnel-dev.tar.gz -C "$netlane_node_dir" && bash "$netlane_node_dir/setup.sh" --join 'https://<main>/<префикс>/node/join#<код>'
   ```

   `setup.sh` спросит домен, название и страну ноды, поставит VPN, маскировку и сертификат
   Let's Encrypt, подключит ноду к main и дождётся первой синхронизации. Без вопросов:
   `NETLANE_YES=1 NETLANE_DOMAIN=de.example.com NETLANE_SERVER_NAME=Франкфурт NETLANE_SERVER_COUNTRY=DE NETLANE_JOIN='…' bash netlane/setup.sh`.
4. Нода появится в разделе «Ноды» и в подписках пользователей.

Если у кого-то из пользователей задана месячная квота, «Добавить ноду» недоступна: каждая
нода считает трафик отдельно, общей квоты нет. Уберите квоту и повторите. Пока есть ноды,
квоту задать нельзя; история расхода в «Обзоре» суммируется по всем локациям.

Уже установленный главный сервер не преобразуется в ноду этой командой. Для ноды нужен VPS без существующей установки Netlane; не удаляйте конфигурацию и базу ради повторного запуска.

## Как это работает

- Нода держит к main долгий запрос (до 25 с). Изменения пользователей в панели («Применить»,
  удаление, «Отключить сессии») приходят на ноды почти сразу. Неприменённые правки на ноды не
  попадают.
- Связь идёт через 443 main по секретному префиксу пути (`sync_prefix` в config.json) за
  сайтом-приманкой. Без верного токена там отвечает обычный сайт. На нодах новых портов нет,
  у ноды нет панели и порта 8443.
- Движок TrustTunnel не передаёт тело запроса на сайт-приманку, поэтому нода отправляет свои
  данные в заголовке `X-Sync-Data` (JSON, gzip, base64url). Ответы main приходят обычным телом.
- Если прокси на пути обрывает долгие запросы, нода сама переходит на опрос раз в 10 секунд
  (заголовок `X-Sync-Poll: 1`, main отвечает сразу).
- Подписка отдаёт то, что получили ноды при последнем «Применить»: сохранённая, но не
  применённая правка не убирает серверы у клиентов.
- Если main недоступен, нода продолжает пускать пользователей из последнего полученного
  списка и повторяет запросы с паузой до 60 с.
- Пароли пользователей передаются нодам только по TLS и только с токеном ноды.

## Группы и доступ к локациям

Группа связывает пользователей с локациями: у пользователя ровно одна группа, и он может
пользоваться только теми локациями, которые в неё входят. Нода обслуживает пользователей
привязанных к ней групп — при синхронизации она получает не всех, а только своих.

- **Главный сервер доступен всегда.** Он точка входа и хост панели, поэтому в списке локаций
  группы его нет: он есть у всех.
- **Группа без локаций означает все локации**, включая ноды, добавленные позже. Так устроена
  группа по умолчанию «Все локации», в которую миграция переносит всех существующих
  пользователей: обновление панели никого не лишает доступа.
- **Группу с участниками удалить нельзя** — сначала переведите людей. Группу по умолчанию
  нельзя удалить и пустой: в неё попадают пользователи, когда ничего другого не задано.
- **DNS и правила общие.** Их задают на главном сервере, они одинаковы для всех и от группы не
  зависят: группа ограничивает только локации.
- **Подписка сужается сама.** Список серверов в приложении приходит из подписки, поэтому
  клиенту не нужны правки: пользователь увидит только локации своей группы.

В панели: раздел «Группы» — создание, локации и число участников; при создании пользователя
группа обязательна; в списке пользователей есть значок группы и фильтр по ней.

## Подписка

У пользователя в диалоге «Профиль» — «Ссылка подписки». Ссылка ведёт на
`https://<main>/<префикс>/sub/<токен>` и отдаёт JSON со всеми локациями: main и нодами, которые
на связи сейчас (синхронизировались за последние 2 минуты): выключенная или удалённая нода пропадает у клиентов при следующем обновлении подписки. «Перевыпустить» сразу отключает старую ссылку. Выключенный
или просроченный пользователь получает пустой список. Клиент Netlane принимает ссылку
подписки кнопкой «Вставить» и обновляет её сам.

## Удалить ноду

«Ноды → Удалить». Токен ноды отзывается; нода при следующем запросе получает отказ, убирает
всех пользователей и перестаёт пускать кого-либо. Чтобы вернуть сервер, переустановите его с
новым кодом приглашения.

## Обслуживание ноды

- Служба: `trusttunnel-node` (агент и сайт-приманка), движок — `trusttunnel-managed`.
- Состояние: `trusttunnel-admin doctor` от пользователя `trusttunnel-admin` показывает время
  последней синхронизации.
- Журнал: `journalctl -u trusttunnel-node`.
- Резервные копии — как на main, включают токен ноды (`/var/lib/trusttunnel-admin/node.token`).

## Правила и DNS через подписку

В главной панели раздел «Маршрутизация» управляет общими настройками всех пользователей подписки. Наборы правил и DNS едины для всех: они хранятся одной записью на главном сервере, приходят клиенту в подписке и группами не настраиваются — группа решает только, какие локации доступны человеку. Можно создать до 10 наборов, каждый содержит до 256 доменов/IPv4/CIDR и до 100 правил приложений. Для приложений указывается имя процесса, например `telegram.exe`, и маршрут `vpn` или `direct`. Полные пути зависят от компьютера и в общих наборах не используются.

После «Сохранить для подписок» наборы передаются в подписке. Windows-клиент забирает их при следующем обновлении подписки; вручную — щелчок по строке аккаунта внизу навигации или «Обновить» на странице «Серверы». Наборы появятся под своими названиями; они защищены от редактирования в клиенте. Пользователь выбирает набор на странице «Подключение» или «Правила»; переименовывать и изменять его можно в панели. Для личных изменений создайте копию набора. Личные наборы при обновлении сохраняются.

DNS настраиваются в том же разделе панели и действуют для серверов этой подписки. Если «Задавать DNS» выключено, клиент использует личные DNS. Если включено с пустым списком, используются DNS движка по умолчанию. Можно указать до восьми публичных DNS. В режиме правил настройки DNS используются для запросов, направленных через VPN.

Обновление правил и DNS применяется к следующему подключению. Действующее соединение продолжает работать с прежними настройками. При удалении набора в панели он исчезнет после обновления подписки; если он был выбран, клиент перейдёт на встроенный «Весь трафик» для следующего подключения. Другие подписки и личные DNS сохраняются.

Старые клиенты продолжают получать серверы и пропускают новые поля. Для правил и DNS подписки требуется обновлённый Windows-клиент. Сохранение настроек в панели проверяет ревизию, чтобы параллельное редактирование из другой сессии не перезаписало изменения молча.
