# Локальное управление TrustTunnel, протокол v1

Это интерфейс экспериментальной сборки endpoint с пятью патчами из `upstream/patches/`. Публичного TCP-порта управления нет. Файлы и Unix-сокет настраиваются флагами `--control-socket` и `--control-state`; оба флага обязательны вместе. Без них сохраняется исходный режим TrustTunnel.

На первом запуске управляемая сборка импортирует существующие credentials как `legacy:<username>`. Импортированные записи нельзя случайно перезаписать пользователем с другим ID из базы панели; миграция старых пользователей в UI ещё предстоит. Изначально в конфигурации должен быть аутентификатор с хотя бы одной записью. После инициализации authoritative-источником пользователей и скорости становится файл managed state. SIGHUP обновляет TLS, но не заменяет пользователей содержимым старого credentials-файла.

## Права и хранение

- Родительские каталоги: 0700 либо 0750, без записи для группы и без доступа посторонних. Создание каталогов и общей служебной группы будет автоматизировано в полном установщике.
- Unix-сокет: 0660. Подключение разрешено владельцу и доверенной служебной группе. Членство в этой группе даёт полный доступ к управлению VPN.
- Файл managed state: 0600. Он содержит восстанавливаемые VPN-пароли в открытом виде, как штатный credentials-файл TrustTunnel; его нельзя публиковать или включать в незашифрованные выгрузки. В SQLite панели пароли по-прежнему зашифрованы отдельным ключом.
- Запись через временный файл, fsync и атомарное переименование. Неисправное или слишком открытое состояние при старте вызывает отказ запуска, а не сброс политик на безлимит.
- Сохраняются версия формата, глобальное поколение и ревизии пользователей. При перезапуске восстанавливаются доступ и скорости; активные сессии не восстанавливаются.

Для разработки каталоги создаются заранее и принадлежат процессу endpoint. Это не финальная инструкция установки для пользователя: в готовом релизе достаточно одной команды и короткого мастера.

## Формат

Одна JSON-строка с `\n`, один ответ и закрытие соединения. Не более 65536 байт запроса/ответа, до 16 соединений одновременно, тайм-аут 5 секунд. Неизвестные операции и поля отклоняются. До 100 записей пользователей, включая импортированные. Пароли в ответах не передаются.

```json
{"op":"status"}
```

Ответ содержит `ok`, `state.version: 1`, `state.generation`, возможности и записи без паролей.

```json
{
  "op": "upsert",
  "expected_generation": 3,
  "user": {
    "id": "stable-user-id",
    "username": "alice",
    "password": "disposable-example-password",
    "revision": 2,
    "enabled": true,
    "download_mbps": 20,
    "upload_mbps": 10
  }
}
```

Конфликт поколения или устаревшая ревизия отклоняются. Повтор с той же ревизией и идентичными значениями проверяет сохранение состояния и возвращает подтверждение без сброса bucket или переподключения. Изменённые значения требуют новой ревизии. Переименование пользователя и перенос имени между ID не допускаются.

```json
{"op":"disconnect","username":"alice"}
```

Возвращает число помеченных транспортных соединений. У них отменяются и фоновые TCP/UDP/ICMP-потоки. Другие пользователи не затрагиваются; новые подключения этого же пользователя допустимы, если доступ не отключён. Ответ означает запрос закрытия, а не ожидание завершения всех сетевых процедур.

## Скорость

Значения в десятичных Мбит/с относительно клиента: скачивание из Интернета и загрузка в Интернет. Ноль — безлимит. Два общих bucket на пользователя; они разделяются всеми его транспортами и потоками и обновляются без перезапуска. Burst — максимум из 64 КиБ и 100 мс заданной скорости. Ограничение действует на полезные данные в точке передачи библиотеке; шифрование, сетевые буферы и повторная передача пакетов могут менять мгновенную скорость сетевого интерфейса.

TCP передаётся порциями до 16 КиБ. Непринятые sink байты возвращаются в bucket и не тарифицируются повторно. UDP и ICMP ожидают бюджет на целую датаграмму; нет новой неограниченной очереди, удерживается по одному пакету на канал, далее работают существующие буферы протокола.

Срок доступа поддерживается третьим патчем: необязательный `expires_at` RFC3339, capability `expiry: true`, поле `expired` в публичном состоянии. Endpoint закрывает активные транспорты и отказывает новым подключениям независимо от панели; дата сохраняется через перезапуск. Контракт времени, продления и совместимости — в [EXPIRY.md](EXPIRY.md). Четвёртый патч добавляет `quota_bytes`, capability `durable_quotas`, признак `quota_exhausted`, текущий `quota_used_bytes` и защищённый журнал расхода. История читается операцией `usage` с месяцем и курсором; контракт сохранности, точности и восстановления — в [QUOTAS.md](QUOTAS.md).

## Проверки

`lib/tests/managed.rs` проверяет на настоящих TLS HTTP/2 и QUIC HTTP/3 соединениях общую скорость в обоих направлениях и адресное закрытие транспорта с сохранением подключения второго пользователя. Сквозной Python-тест проверяет API панели, Unix RPC, TLS CONNECT, блокировку, переподключение, перезапуск, идемпотентность, отказ неподдерживаемых квот и отказ старта с испорченным состоянием. Матрица настоящих мобильных/настольных клиентов и системные VM ещё впереди.

## Удаление

Capability `remove_user: true`, начиная с preview.5. Запрос:

```json
{"op":"remove","expected_generation":3,"id":"immutable-user-id","username":"alice","expected_revision":2}
```

Команда сверяет поколение, ID, имя и ревизию; сохраняет новое состояние с fsync и атомарной заменой, отзывает credentials и сессии и возвращает обычный `state` без пользователя. История расхода по ID не удаляется. При уже отсутствующем ID повтор сохраняет барьер долговечности и не увеличивает поколение; пользователь с тем же именем и новым ID не затрагивается. Ошибка fsync не выдаётся за успешное удаление. Управление исключительно локальное и доверенное; браузер обращается к защищённому DELETE API панели.
