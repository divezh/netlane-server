# HTTP API панели

В VPS-комплекте API доступен по `https://<домен>:8443/api/v1` в рамках выбранной политики доступа. По умолчанию панель слушает loopback; `127.0.0.1:8080` используется отдельной конфигурацией разработки. Внешний интерфейс требует TLS; reverse proxy не входит в штатную схему. При заданном `control_socket` панель обращается к управляемому endpoint по локальному Unix-сокету. Рабочий веб-интерфейс доступен по `/`; файлы `design/` и `/preview/` — отдельные демонстрационные эскизы; с 0.5.17 `/preview/` открывается только после входа.

`setup` запрашивает домен и пароль администратора с подтверждением; логин по умолчанию `admin`. Забытый пароль сбрасывается на сервере командой `trusttunnel-admin passwd` от root (либо `--password-stdin`), затем `systemctl restart trusttunnel-admin`. Входы пишутся в журнал службы: `auth: login ok|login failed|login rate limited ... ip=…`; успешные входы и смена пароля попадают и в аудит с IP. Неудачные входы в аудит не пишутся, чтобы перебор не раздувал базу; их учитывает fail2ban. Настройки создаются однократно, повторный запуск не заменяет конфигурацию. Пароль администратора хранится как Argon2id. VPN-пароли зашифрованы AES-GCM, ключ лежит в защищённой конфигурации вне базы. Для восстановления нужны и БД, и ключ. Стадия проекта и ограничения описаны в [README](../README.md).

Для POST/PUT после входа нужен заголовок `X-CSRF-Token`. JSON-запросы должны иметь `Content-Type: application/json`. Неизвестные поля и несколько JSON-объектов в одном запросе отклоняются. Вход ограничен пятью попытками в минуту на адрес (IPv6 — на сеть /64) и 60 попытками в минуту всего; одновременно вычисляются не более двух Argon2-хешей. Сессии живут восемь часов, заканчиваются после двух часов без запросов и сбрасываются при перезапуске панели. Журнал хранит события год. TOTP и резервные коды настраиваются через `/api/v1/auth/2fa`.

При наличии нод `GET /api/v1/users` добавляет каждому `locations: {applied, total}`, считая только локации его группы, а квота (`quota_bytes > 0`) в `POST`/`PUT` отклоняется кодом 409 `quota_not_supported_with_nodes`. `/usage` суммирует расход по main и нодам. «Отключить сессии» ставит команду каждой ноде.

### Протокол нод и подписка

Обслуживаются сервером сайта-приманки (за 443 VPN-сервера) по секретному префиксу `sync_prefix` из `config.json`; любой неверный запрос получает ответ сайта-приманки. Тело запроса движок не передаёт, поэтому нода кладёт JSON в заголовок `X-Sync-Data` (gzip, base64url); тело тоже принимается.

| Метод | Путь | Поведение |
|---|---|---|
| POST | `/<prefix>/node/join` | `{code, name, country, domain, endpoint_version}` → `{node_id, node_token}` |
| POST | `/<prefix>/node/sync` | `Authorization: Bearer <token>`, отчёт `{revision, users, usage, presence, acked_commands, endpoint_version}`; долгий опрос до 25 с (с заголовком `X-Sync-Poll: 1` — ответ сразу); ответ `{revision, users, commands}` или `{revision, unchanged: true}`; 401 только для неизвестного или отозванного токена, без токена — ответ сайта-приманки. `users` содержит только пользователей групп, покрывающих эту ноду |
| GET | `/<prefix>/sub/<token>` | `{version: 1, name, update_hours, servers: [{id, name, country, link}]}` — main и ноды группы на связи (синхронизация за 2 минуты), `update_hours` = 12; пустой список для выключенного пользователя. С 0.5.18 — блок `account` без учётных данных: `status` (`active`, `pending` — ещё не применён, `disabled`, `expired`, `exhausted` — квота месяца исчерпана), `expires_at` при сроке, `quota_bytes`, `quota_used_bytes` и `quota_month` при квоте (только с управляемым endpoint главного сервера) |

Подробности — в [NODES.md](NODES.md).

Пример создания пользователя:

```json
{
  "username": "alex",
  "group_id": "all",
  "policy": {
    "enabled": true,
    "quota_bytes": 0,
    "download_mbps": 20,
    "upload_mbps": 10
  }
}
```

Если `password` опущен, генерируется случайный пароль; он возвращается только в ответе создания. Пароль также входит в профиль подключения, выдаваемый отдельным авторизованным действием. `quota_bytes: 0` и скорость `0` означают безлимит. Создание/изменение возвращает `vpn_applied: false`; затем администратор вызывает `/apply`. Несовпадение ожидаемой ревизии даёт 409, предотвращая потерю параллельных изменений.

Включённая `quota_bytes` применяется при capability `durable_quotas: true`; на старой версии — 409 `endpoint_quota_not_supported`. Квота общая для обоих направлений и всех соединений, месяц — UTC. Необязательный `expires_at` RFC3339 требует capability `expiry: true`; на старой версии включённая политика со сроком получает 409 `endpoint_expiry_not_supported`. Отключение возможно независимо от сохранённых квоты и срока: неподдерживаемые поля не передаются старому endpoint, доступ закрывается. Профиль истёкшего либо исчерпавшего квоту пользователя не выдаётся: 409 `user_expired` / `user_quota_exhausted`. Контракты — в [EXPIRY.md](EXPIRY.md) и [QUOTAS.md](QUOTAS.md).

`/apply` сверяет глобальное поколение endpoint, передаёт пользователя по Unix-сокету, проверяет подтверждённые ID, имя, ревизию и скорости и только затем записывает `applied_revision`. Если пользователь параллельно отредактирован, подтверждение старой ревизии не выдаётся за применение новой. Повторное применение идентичной ревизии идемпотентно, не сбрасывает общий лимитер и не разрывает остальные подключения. Запрос и подтверждение фиксируются в аудите без секретов.

`/disconnect` возвращает `disconnect_requested` — количество помеченных для закрытия транспортных соединений. Закрываются и их активные потоки; команда допускает последующее переподключение. Для запрета переподключений надо применить `enabled: false`. В управляемом режиме один транспорт привязан к одному пользователю; попытка использовать в нём чужие credentials отклоняется.

Тайм-аут RPC не доказывает отсутствие изменений на endpoint. Панель не помечает политику применённой без подтверждения; безопасное восстановление — повторный `/apply` с той же ревизией. Состояние endpoint доступно через `/endpoint/control`. Отказ сохранения состояния также не даёт успешного подтверждения.

Накопительные счётчики `/clients` считаются с момента запуска endpoint. Это сырые показания для диагностики, не сохраняемый учёт месячной квоты. API не делает вид, что недоступный endpoint передал нулевой трафик.

`/profile` требует включённого пользователя с совпадающими желаемой и применённой ревизиями, затем сверяет актуальное подтверждение endpoint. Выдача записывается как `user.profile_exported` до возврата credentials. Без CSRF — 403, при неприменённом/отключённом доступе — 409. Ответ содержит пароль: не записывать его в логи. TLS-проверка в профиле всегда включена, IPv6 консервативно выключен, порт VPN — 443. Ссылка формата v1 соответствует закреплённому endpoint. Порт 443 — текущий фиксированный контракт экспортера, на нестандартном порту профиль пока вручную проверяется перед использованием.

Удаление требует сессии, CSRF, `expected_revision` текущей записи и capability `remove_user`. Изменение политики, применение и удаление сериализованы. Панель запрашивает статус, отправляет `remove` с поколением и ревизией endpoint и проверяет отсутствие ID и имени в подтверждении. Затем транзакционно удаляет пользователя и зашифрованный пароль из SQLite, записывая `user.deleted`; аудит и расход остаются. На недоступном endpoint — 503, неподдерживаемом — 409, несовпавшем подтверждении — 502; запись не удаляется. Потерянный ответ можно безопасно повторить. Если endpoint уже удалил доступ, а SQLite не завершила транзакцию, ответ `removed_but_reconciliation_required`: повторить удаление после устранения ошибки хранения.
