# Установка и обслуживание

Основные команды — в [README](../README.md). Готовый комплект скачивается из [Releases](https://github.com/divezh/netlane-server/releases/latest); сборка на VPS не нужна.

## Требования

- Чистый VPS x86_64, systemd, root, публичный IPv4, от 1 ГБ RAM и 10 ГБ диска. Для запаса рекомендуется 2 ГБ RAM.
- Ubuntu 24.04 LTS — основной проверенный вариант. Установщик также поддерживает Ubuntu 26.04 и Debian 13. Ubuntu 26.04 проверена локально с настоящим systemd в контейнерах; полная автоматическая VM-матрица отсутствует.
- A-запись домена указывает на VPS. В Cloudflare используется DNS only. Ошибочную AAAA-запись на другой адрес нужно исправить.
- Доступны SSH, TCP 80/443 и UDP 443. TCP 8443 нужен только для явно разрешённого внешнего доступа к главной панели.
- На портах установки не должны работать другой VPN, nginx или Apache. Для существующего сервера с другими службами требуется отдельное планирование портов.

## Что запускается

`setup.sh` — мастер: проверяет сервер, запрашивает настройки и подготавливает систему. Он вызывает `install.sh`, который устанавливает VPN и панель, создаёт конфигурации и systemd-службы, получает сертификат и проверяет готовность.

Для новой ноды используйте приглашение из главной панели: [порядок подключения](NODES.md). Нода не имеет отдельной панели и не открывает 8443. Существующий главный сервер этой командой в ноду не преобразуется.

## Доступ к панели

Мастер предлагает текущий IP, список адресов, публичный порт или локальный доступ через SSH. По умолчанию панель слушает `127.0.0.1:8443`; внешний доступ включается явно. Порт у хостинга должен соответствовать выбранной политике.

Для локального доступа откройте туннель с компьютера администратора:

```bash
ssh -L 8443:127.0.0.1:8443 root@IP_VPS
```

Для браузера домен сертификата должен разрешаться в `127.0.0.1`: временно добавьте `127.0.0.1 vpn.example.com` в локальный `hosts`, затем откройте `https://vpn.example.com:8443`. Удалите эту запись после администрирования: она также меняет адрес VPN-сервера для приложений на этом компьютере. Не отключайте проверку сертификата.

Логин — `admin`, пароль задаётся или генерируется мастером. После входа включите 2FA в «Безопасности» и сохраните коды восстановления.

## Обновление и резервные копии

Обновляйте главный сервер и каждую ноду кнопкой в панели или `sudo netlane-update` ([подробнее](UPDATES.md)). Обновлятор проверяет комплект, делает резервную копию, обновляет программы и проверяет службы. При неуспешной проверке пытается вернуть предыдущие бинарники. `setup.sh` не является обновлятором.

Копии находятся в `/var/backups/trusttunnel`: ежедневно около 04:00 MSK, случайная задержка до 10 минут, хранятся 14 последних. Копия согласованная: службы могут кратковременно останавливаться. Переносите архивы в защищённое внешнее хранилище; в них есть секреты.

Ручной запуск:

```bash
systemctl start trusttunnel-backup.service
```

Для восстановления нужны база, исходная конфигурация с ключом шифрования и состояние endpoint. [Учёт квот и резервное копирование](QUOTAS.md).

## Рабочие файлы

| Путь | Содержимое |
| --- | --- |
| `/opt/trusttunnel/bin/` | VPN endpoint |
| `/opt/trusttunnel-admin/bin/` | Панель, агент ноды, резервное копирование |
| `/etc/trusttunnel/` | VPN-конфигурация, credentials и TLS |
| `/etc/trusttunnel-admin/` | Конфигурация панели/ноды, ключ шифрования, TLS |
| `/var/lib/trusttunnel/` | Managed state и журнал расхода |
| `/var/lib/trusttunnel-admin/` | SQLite, токен и состояние ноды |
| `/run/trusttunnel/control.sock` | Локальное управление VPN |
| `/var/lib/netlane-install/` | Состояние незавершённой установки |

Папки распаковки в `/root/netlane*` можно удалять после успешной установки/обновления. Рабочие каталоги выше для очистки не удаляйте.

## Диагностика

```bash
systemctl status trusttunnel-managed trusttunnel-admin --no-pager
/opt/trusttunnel-admin/bin/trusttunnel-admin doctor
journalctl -u trusttunnel-admin -u trusttunnel-managed -n 80 --no-pager
```

На ноде вместо `trusttunnel-admin` проверяйте службу `trusttunnel-node`.

| Симптом | Что проверить |
| --- | --- |
| Не выдан сертификат | DNS, TCP 80, время, `/var/log/letsencrypt/letsencrypt.log` |
| Панель недоступна | Выбранную политику доступа, firewall хостинга/UFW, TLS и службу панели |
| HTTP/2 работает, HTTP/3 нет | Доступность UDP 443 у провайдера и клиента |
| Нода без дашборда | Версию панели и агента; первые два замера, выбранную локацию |
| Установка прервана | `/var/log/netlane-setup-install.log`, затем [восстановление с --resume](INSTALLER-RECOVERY.md) |

Не удаляйте `config.json`, базу и журнал квот ради повторной установки. Не выкладывайте их содержимое в отчёты об ошибках.
