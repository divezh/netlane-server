# Проверка веб-интерфейса

Основной регрессионный сценарий — `scripts/test-web-presence.mjs`: он открывает настоящий интерфейс в локальном Edge и подменяет API тестовыми ответами. VPS и рабочие пользователи не используются.

## Запуск

Нужны Node.js, Edge и установленный вне серверного приложения `playwright-core`:

```bash
node scripts/test-web-presence.mjs
```

Если пакет установлен отдельно, задайте `TT_PLAYWRIGHT_MODULE` полным путём к его `index.mjs`. Результаты и снимки сохраняются в `artifacts/`.

## Что проверяется

- Уникальные пользователи и транспортные соединения считаются раздельно.
- Автообновление, текущие скорости, сбросы счётчиков и отсутствие метрик.
- Сохранение поиска, фильтров и фокуса на странице пользователей.
- Выбор ноды, отдельные показатели локации, потеря связи и удаление ноды.
- Отсутствие подстановки метрик главного сервера вместо ноды.
- Пустая/устаревшая история и недоступная статистика.
- Ширины 390, 768, 1440, 1920 и 2560 px без горизонтального переполнения.

## Ручная проверка

На локальном стенде проверьте вход/выход и 2FA, создание/редактирование/удаление тестового пользователя, профили и подписки, приглашение ноды, правила и DNS. Для опасных действий проверьте отмену и ошибку API; секреты на снимках закрывайте или используйте демоданные.

Проверяйте начальное состояние, загрузку, успех, ошибку, пустой список и клавиатурный фокус. Изменения интерфейса не должны показывать вымышленные нули вместо отсутствующих измерений или сбрасывать заполненную форму при автообновлении.

Исторические отчёты о дизайне и проверках находятся в [архиве](archive/WEB_QA.md).
