# Срок доступа

Managed endpoint `-admin-preview.3` принимает необязательное поле `expires_at` в RFC3339 с часовым поясом. Отсутствующее поле означает бессрочный доступ. Пустая строка в политике панели снимает срок; в Unix RPC поле при этом опускается. В сохранённом managed state остаётся абсолютный срок, а не длительность от запуска.

## Поведение

- При наступлении срока новые запросы пользователя не получают доступ к VPN.
- Открытые транспорты и связанные TCP/UDP-потоки закрываются, в том числе когда пользователь простаивает. Управляющая панель для этого не нужна.
- Скоростной лимитер проверяет доступ перед передачей полезных данных; уже переданные ОС или сетевой библиотеке байты отозвать нельзя.
- Продление применяется новой ревизией и будит ожидающие таймеры. Старый таймер не закрывает продлённое соединение. После уже наступившего срока старый транспорт не оживает — клиент подключается заново.
- Повтор применения той же ревизии не начинает новый срок. Перезапуск endpoint заново проверяет сохранённую дату; остановка или перезапуск панели не продлевает доступ.
- Применение отключённого доступа остаётся возможным на старом endpoint даже при сохранённом сроке в базе: неподдерживаемое поле не передаётся, доступ закрывается. Включить ограниченный срок на старой версии нельзя — API возвращает 409.
- Экспорт профиля истёкшего пользователя возвращает 409 `user_expired`. Исходный пароль не меняется автоматически; продление разрешает новое подключение с прежними credentials.

Endpoint сообщает capability `expiry: true`, исходное `expires_at` и вычисляемый признак `expired`. `enabled` означает административное разрешение, а не гарантию действующего срока. Подтверждение применения обязано содержать ту же дату, что и запрос; отсутствие даты не выдаётся за успешное применение ограничения.

Время задаётся в UI в часовом поясе устройства и передаётся в UTC. Неизменённая дата сохраняется без потери исходной точности и часового пояса. Endpoint сравнивает время с точностью до миллисекунд; активный таймер также перепроверяет системное UTC не реже раза в секунду, чтобы заметить перевод часов вперёд. Наблюдённое истечение фиксируется в памяти до изменения даты и не отменяется небольшим обратным переводом часов. После перезапуска используется системное время: корректная синхронизация часов VPS необходима.

## Совместимость и откат

Старые managed-файлы без поля даты читаются без изменений. Добавление срока — расширение версии 1 с согласованием capability; старые endpoint отклоняют неизвестное поле вместо выдачи бессрочного доступа. После записи срока нельзя просто откатить endpoint на `preview.2`: он откажется читать такой managed state. Для отката нужна согласованная резервная копия состояния и проверка политик панели; редактировать файл под работающим endpoint нельзя.

## Проверки

- Модульные Rust-тесты: граница даты, повтор применения, фиксация истечения, продление и снятие срока, закрытие простаивающего транспорта, разбор даты и восстановление из приватного состояния.
- Настоящие TLS HTTP/2 и QUIC: закрытие TCP-транспорта по сроку при сохранении второго пользователя, закрытие UDP-мультиплексора после подтверждённой передачи настоящей датаграммы.
- API → Unix RPC → TLS CONNECT: продление открытого соединения, работа после старого срока, закрытие по новому при остановленной панели, запрет переподключения после перезапуска endpoint, отказ экспорта, снятие срока.
- Go race-тест: отказ старому endpoint, безопасное отключение на старой версии, проверка подтверждения даты.
- Браузер: поле даты, быстрое продление, истёкший статус, отказ профиля, повторное разрешение после продления; три ширины экрана.

Месячная квота и история добавлены в `preview.4`; контракт — в [QUOTAS.md](QUOTAS.md).

## Приёмка VPS

Версия `preview.3` установлена на тестовом VPS с приватной резервной копией базы, конфигурации, managed state и прежних бинарников. Перед открытием панели после обновления проверено полное совпадение трёх существовавших политик; данные владельца не заменялись тестовыми.

Через настоящий TLS VPN получен HTTPS 200 от внешнего сайта, открытое соединение закрылось по короткому сроку, повторное подключение и выдача профиля были отклонены. Продление восстановило HTTPS-доступ; затем тестовая учётная запись отключена. Браузерный цикл срока и продления также прошёл на VPS. Срок задавался по времени сервера: часы рабочего компьютера отличались примерно на три секунды. Статус в UI берётся из `expired` endpoint, поэтому часы браузера не объявляют доступ истёкшим раньше сервера. На VPS подтверждена синхронизация NTP.
