# Месячная квота и история трафика

Endpoint `-admin-preview.4` ограничивает общий объём загрузки и отдачи для неизменяемого ID пользователя. Месяц календарный, по UTC: бюджет следующего месяца начинается в 00:00 первого числа. `quota_bytes: 0` отключает ограничение, но сохраняет учёт. В панели лимит задаётся в ГиБ: 1 ГиБ = 1 073 741 824 байта. Максимум — 1 ПиБ.

## Что учитывается

Считаются полезные данные TCP, UDP и ICMP в точке их принятия библиотекой передачи. Внутренний TLS HTTPS-соединения также является передаваемыми данными; накладные расходы внешнего H2/QUIC, повторные передачи и заголовки внешнего TLS не являются этой квотой. Уже принятые сетевой библиотекой байты нельзя отозвать.

Бюджет общий для всех транспортов и обоих направлений. Параллельные потоки не умножают квоту. TCP может передать только разрешённую часть блока; датаграмма допускается целиком либо не передаётся. Непринятые sink байты и отменённые до отправки разрешения возвращаются в доступный резерв. При исчерпании нет новых передач, а транспорт закрывается. Новый месяц разрешает переподключение; ранее закрытый транспорт не оживает.

Изменение скорости, повторное применение ревизии, отключение/включение доступа и переход на безлимит не обнуляют историю. Если новый лимит ниже уже учтённого расхода, доступ остаётся закрытым; повышение лимита даёт разницу, а не новый полный бюджет. Данные учитываются в месяце выдачи разрешения на передачу, в том числе если буфер сети отправит их позже границы месяца.

## Долговечность и точность

Перед передачей endpoint синхронно сохраняет кредит размером до 1 МиБ на пользователя в приватный append-only журнал. Кредит общий для всех потоков и направлений. Обычные блоки до 16 КиБ используют этот кредит в памяти; fsync не требуется на каждый сетевой блок. Дисковые операции пополнения выполняются вне потока Tokio.

Каждые 30 секунд checkpoint уточняет направления расхода и возвращает неотправленный кредит в свободный месячный бюджет. При аварии либо остановке между checkpoint недоиспользованный кредит не выдаётся повторно. Поэтому после перезапуска до 1 МиБ на пользователя в месяце за такой перезапуск может учитываться консервативно. Это сознательный запас в сторону запрета превышения квоты, а не обещание побайтовой точности после сбоя. Для малой квоты кредит ограничен её остатком.

В истории:

- `charged_bytes` — учтённый объём, включая консервативно сохранённый резерв;
- `upload_bytes`, `download_bytes` — подтверждённые объёмы по направлениям;
- `uncertain_bytes` — часть учтённого объёма, которую после сбоя нельзя точно распределить между отправленными данными и неиспользованным резервом;
- `reserved_bytes` и `in_flight_bytes` — диагностические данные бюджета, не дополнительный расход поверх `charged_bytes`.

В отсутствие текущих незавершённых передач учтённый объём равен сумме загрузки, отдачи и неуточнённого резерва. API месячных итогов и строки первой страницы строятся из одного снимка. История хранится за 24 месяца; старт учёта явно указан. Старые `/clients` не превращаются в вымышленную историю до установки функции.

## Файлы и отказ при сбое

Для `/var/lib/trusttunnel/managed.json` журнал — `/var/lib/trusttunnel/managed.usage.jsonl`, блокировка — `managed.usage.lock`. Данные и блокировка имеют права 0600, каталог — 0700 либо 0750 без записи группы. Второй процесс с тем же журналом не допускается. Записи защищены SHA-256 от случайного повреждения; неполная последняя строка также считается ошибкой. По достижении 8 МиБ журнал атомарно уплотняется с fsync файла и каталога.

После первого создания журнала в managed state сохраняется `usage_version: 1`. Отсутствующий, пустой, повреждённый или слишком открытый обязательный журнал вызывает отказ запуска. Ошибка записи запрещает новые разрешения на передачу, включая попытку снять квоту. Переход календаря назад за последний сохранённый месяц также блокирует доступ; корректное NTP-время сервера обязательно.

## API

Capability `durable_quotas: true` разрешает применять `quota_bytes`. API сверяет подтверждённый лимит с запросом. На старом endpoint включённый лимит получает 409 `endpoint_quota_not_supported`; отключить доступ можно независимо от сохранённого лимита. Профиль пользователя с исчерпанной квотой не выдаётся: 409 `user_quota_exhausted`.

`GET /api/v1/usage?month=2026-11&after=<ID>` требует сессии администратора. Ответ содержит месяц, начало учёта, доступные месяцы, строки расхода, итоги месяца и `next_after`. Unix RPC — `{"op":"usage","month":"2026-11","after":""}`. Страница до 100 строк сохраняет ограничение ответа 64 КиБ; итоги относятся ко всему месяцу, а не только странице. Недоступный месяц не заменяется нулевым историческим расходом.

## Резервирование и восстановление

Для согласованной резервной копии остановить панель и endpoint, затем сохранить БД, конфигурацию с ключом шифрования, `managed.json` и `managed.usage.jsonl` вместе. `managed.usage.lock` не содержит расхода и не восстанавливается как состояние процесса. В готовом обновляющем механизме этот порядок должен выполняться автоматически.

Нельзя восстанавливать один managed-файл или старую копию журнала поверх работающего VPN: это может потерять учтённый после копии трафик. При откате совместимого бинарника текущий корректный журнал расхода сохраняется. Откат на `preview.3` не поддерживает квоты и требует отдельного согласованного восстановления; он не является способом обойти исчерпанный бюджет.

## Проверки

Проверены общий бюджет 24 конкурентных потоков, оба направления, возврат неотправленных данных, изменение лимита без сброса, граница UTC-месяца, ограничение истории, checkpoint, уплотнение, повреждение, права файлов и отказ записи. Настоящие H2/QUIC-тесты проверяют параллельные транспорты и реальные UDP-датаграммы с квотой. Сквозной тест убивает endpoint через SIGKILL, восстанавливает остаток, проверяет отказ переподключения и профиля, затем повышение лимита без сброса. Браузерный тест передаёт реальные 256 байт, проверяет месячную статистику и блокировку после снижения лимита.
